# 行动模式：营切换与战况简报（0.1.15）

当前音乐流程使用 [0.1.14 行动音乐状态机](operations-music.md)。下文0.1.12音乐段落保留历史行为，实际曲目、决战条件和播放优先级以状态机文档为准。

区域占领与撤退清理播报见 [0.1.15 行动语音说明](operations-voice.md)。

房间列表中的原“突破 / Breakthrough”改为“行动 / Operations”。配置路径、玩法 ID 仍沿用 `breakthrough`，旧地图的区域、据点和部署位置可以继续使用。

## 配置镜头

与现有部署镜头和结算镜头的选择方式相同：管理员先站到希望作为简报镜头的位置，调整好朝向和俯仰角，再执行：

```text
/gdc room <房间ID> config breakthrough btBriefingViewPosition here
```

`here` 同时记录 X/Y/Z、yaw、pitch；也支持现有的 `x,y,z,yaw,pitch` 格式。坐标与其他镜头配置一致，X/Z 使用所在方块中心，Y 保留小数。建议选能俯瞰所有区域及双方大本营的高处，并朝地图中心看；镜头前方应能覆盖各区域完整边界。

另外三个参数：

```text
/gdc room <房间ID> config breakthrough btBattalionCount 3
/gdc room <房间ID> config breakthrough btBriefingSeconds 20
/gdc room <房间ID> config breakthrough btPreparationSeconds 10
/gdc room <房间ID> saveRoom
```

这些字段也接入原房间配置界面：简报镜头在“传送”分类，营数和时长在“规则”分类。

| 参数 | 默认值 | 范围 | 含义 |
| --- | --- | --- | --- |
| `btBattalionCount` | 3 | 1–10 | 进攻方总营数 |
| `btBriefingSeconds` | 20 秒 | 8–600 秒 | 到达简报镜头之后的演示时长，不包含往返飞行、退场淡出和攻势提示 |
| `btPreparationSeconds` | 10 秒 | 1–300 秒 | 返回部署位置后才开始的准备时间 |

旧 JSON 缺少营配置时自动使用默认值。多营房间启动前需要补设 `btBriefingViewPosition`；单营房间若未设置则使用当前区域部署镜头作为后备简报镜头。运行中的对局使用开局读取的营参数，新参数在下一场生效。

## 演示流程

本营兵力耗尽或当前区域进攻超时后，服务器立即暂停占领、伤害、复活／救援／部署推进，保留人物、倒地模型、尸体及载具供结果镜头和飞行观看。玩家本体在飞行期间留在原处；简报开始才清理旧玩家流程和本房间全部在场载具，清理不计死亡、击杀或比分，不触发载具爆炸。

1. 立即锁定移动、开火、物品使用等战场操作，保留鼠标与聊天。镜头开始第三人称拉出时即隐藏已识别的原版及模组战斗 HUD（包括血量、快捷栏、准星、枪械信息、击杀提示等），保留结果文字、时间轴字幕、聊天与结算退出按钮；到下一营部署准备时恢复部署界面所需显示。结果阶段共 **3 秒**：前 **0.5 秒**快速拉到角色后上方的第三人称镜头，碰到地形时收近镜头；拉出完成后停留 **1 秒**。主标题在总时间 **1.5 秒**开始用 **0.3 秒**淡入，副标题在 **2.5 秒**开始用 **0.3 秒**淡入。防守方显示“我们赢了 / 成功防守本区域”，进攻方显示“我们输了 / 无法拿下本区域”。文字采用白色、加大字距、无描边的居中两行，上方大标题、下方小副标题。
2. 总时间 **3 秒**开始用 **7 秒**平滑飞到简报位置，同时转到配置角度。飞行第 **4 秒**（总时间 **7 秒**），结果两行文字用 **1 秒**淡出，普通区域及进攻方大本营边界同时用 **1 秒**淡入，此时没有遮罩。飞行第 **6 秒**（总时间 **9 秒**），对应半透明遮罩用 **1 秒**淡入，到位时边界、遮罩均完整显示。防守方大本营不参与显示；进攻方大本营始终按所属阵营着色，己方蓝、敌方红。
3. 总时间 **10 秒**镜头到位，才清理旧人物状态、尸体和载具，并开始 `btBriefingSeconds`。简报不再显示“战况简报 · 第 X/Y 营”标题，镜头保持配置的简报位置。
4. 普通区域在飞行途中统一表示防守方所有，到位时第一处已完整攻占的区域立即换为进攻方颜色，然后每隔 **0.5 秒**瞬时切换下一处，不再逐渐混色；当前尚未攻下的区域保持防守方颜色。进攻方攻到第三区时，第一、第二区依次由红变蓝，第三区仍为红色；防守方看到相反配色。
5. 简报时长结束后，用 **1 秒**淡出全部边界和遮罩。颜色保持最终战况，不回放归属变化。
6. 遮罩消失后，在画面中央偏上显示 **5 秒**提示。双方统一按进攻方剩余营数计数，与剩余区域数无关：进攻方显示“剩余X轮进攻”或“最后攻势”；防守方显示“剩余X道防线”或“最后防线”。文字采用白色疏排样式，用 **0.1 秒**淡入，最后 **0.1 秒**淡出；期间保持简报镜头，战场操作仍锁定，鼠标与聊天可用。
7. 提示结束后用 **2 秒**平滑返回当前区域的部署镜头。
8. 到位后恢复原部署图标、边界、鼠标和配装入口，并开始准备倒计时，准备结束后使用原部署流程。

`btBriefingSeconds` 控制镜头到位之后到边界、遮罩开始退场之前的整段时长，包含瞬时换色和最终画面的停留。提前在飞行途中淡入边界、遮罩不会占用或延长该配置时长。六处区域依次瞬时换色在到位后的 **2.5 秒**内完成，简报时长仍保留 **8 秒**下限。默认简报 20 秒时，第 10–30 秒保持简报，第 30–31 秒退场，第 31–36 秒显示提示，第 36–38 秒返回，第 38 秒进入第二营部署界面。

换营保留已经完整占领的区域，当前未突破区域的据点归属与进度恢复到防守方，并按重新计算的上限补满新营兵力。房间配置显示“进攻方进攻时间（分钟，0为无限）”，内部参数仍为 `btStageDurationMinutes`。每个区域开始作战时重新计时，有限时间耗尽即判定进攻方本营进攻失败，进入营结算；设为 `0` 时无限时间且不显示顶部时间指示器。零兵力争夺不受进攻超时限制：原为有限时间时显示 `--:--`，原为无限时间时仍隐藏时间指示器。退场后的准备和推进倒计时仍使用各自的显示。

进攻方拿下全部区域，或最后一营耗尽时，仍先显示结果和简报；遮罩淡出后，在原攻势提示的位置显示“行动胜利”或“行动失败”，按玩家所属阵营判定，持续 5 秒，字号、字距及淡入淡出沿用攻势提示。全程留在战况简报镜头，不返回新营部署。拿下全部区域的开头结果文案相应改为攻方“我们赢了 / 已拿下所有区域”、守方“我们输了 / 所有区域皆已沦陷”。整场结算触发时机由下述配置决定。

## 兵力规则（0.1.2）

规则分类中的兵力参数：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `btTroopsPerPlayer` | 20 | 每位参考阵营玩家提供的兵力，支持正数小数 |
| `btTroopBalanceReference` | 根据防守方计算 | 也可选择根据进攻方计算 |
| `btMaxAttackTroops` | 250 | 人数计算结果允许的最大上限，须为正整数 |
| `btStageTroopReward` | 50 | 每次完整攻占区域发放的固定补兵，允许设为 0 |
| `btTroopGainPerDefenderKill` | 3 | 清理撤退守军时，每次符合条件的击杀补兵 |

```text
/gdc room <房间ID> config breakthrough btTroopsPerPlayer 20
/gdc room <房间ID> config breakthrough btTroopBalanceReference 根据防守方计算
/gdc room <房间ID> config breakthrough btMaxAttackTroops 250
/gdc room <房间ID> config breakthrough btStageTroopReward 50
/gdc room <房间ID> config breakthrough btTroopGainPerDefenderKill 3
/gdc room <房间ID> saveRoom
```

上限 = `min(最大兵力上限, 向上取整(参考阵营人数 × 每人提供兵力数))`。人数沿用原规则，统计房间内属于参考阵营的参战玩家，包括倒地、死亡和部署中的成员；观战人员不计入参考阵营。开局、新营准备开始时计算上限并补满。区域攻占成功时按当时人数计算下一阶段上限，实际进入下一阶段时不再计算，也不再次补兵。阶段作战中加入或退出不会立即改变本阶段的上限，在下次区域攻占或新营开始时生效。

区域攻占成功后的固定顺序：

1. 更新上限。上限增加不自动补兵；上限降低也不裁掉已有的超额兵力。
2. 当前兵力不足 50 时，先补至 `min(50, 新上限)`；如果当前兵力已经超出新上限，则原样保留。
3. 发放 `btStageTroopReward`，仅补充新上限以内的空缺。
4. 后续清理撤退守军期间逐次发放击杀奖励，同样不会溢出上限或裁掉原有超额兵力。

例如新上限为 200、攻占时剩 20，则先补至 50，再增加默认 50，得到 100；之后击杀五名撤退守军增加 15，得到 115。若新上限为 70，同样剩 20，则最终只能补至 70。若已有 160、上限降到 100，则仍保留 160，后续自然消耗至低于上限后才允许补兵。区域奖励仅发放一次，进入撤退、推进倒计时和下一阶段不会重复领取。

进攻方倒地不扣兵力，成功救援不扣兵力，确认死亡在正常作战阶段扣 1。防守方普通死亡不减少进攻方兵力。撤退和推进倒计时期间进攻方死亡不扣兵力；本次尚未成功撤退的防守方，因撤退超时或被进攻方击杀而确认死亡时提供一次奖励；已成功撤退后折返不提供奖励。换营清理、传送和重生不扣兵力。

旧房间 JSON 的 `maxAttackTroopsAt12Players` 读取时自动除以 12，转换为 `troopsPerPlayer`；已有的明确计算基准和击杀奖励保留，缺少的新字段使用默认值。保存后只写新字段，不会反复除以 12。原 `btMaxAttackTroopsAt12Players` 配置入口移除，改用 `btTroopsPerPlayer`；不要直接把旧数值填入新配置。

## 撤退规则（0.1.3）

区域攻占后，记录此刻旧区域内存活且不在死亡/部署流程中的防守方作为本次撤退人员。未完成撤退期间保留双方可见的追踪标记，画面显示两行白色提示：上行“撤退至下一区域”、下行剩余秒数。字号、字距、阴影和位置与现有“回到战斗区域”警告共用同一绘制方式，不再使用原生标题或长时限动作栏提示。

到达下一阶段及其后的合法防守区域、或防守方大本营，即完成本次撤退。完成状态不可逆；重新进入旧区域按界外处理，显示原界外警告，不会重新获得撤退标记，也不会提供撤退补兵。界外被进攻方击杀保留原来源，界外倒计时耗尽沿用“逃兵”处决，均沿用现有禁止救援规则。

| 情况 | 死亡提示与来源 | 救援 | 进攻方补兵 |
| --- | --- | --- | --- |
| 撤退时限结束，仍未完成撤退 | 立即处决，显示“撤退失败”；无击杀者、无击杀卡，不归因于最近攻击者 | 不可救援 | 每人一次 `btTroopGainPerDefenderKill`，默认 3 |
| 撤退人员被进攻方击杀 | 显示原击杀者、武器等来源，同时在上方显示“撤退失败” | 不可救援 | 同上 |
| 撤退成功后折返旧区域 | 原界外被击杀或“逃兵”流程 | 沿用界外禁止救援 | 无撤退奖励 |

补兵仍受攻占时已更新的下一阶段兵力上限限制；已有超额兵力不会被裁掉。自然伤害、管理员处决、重新部署和退出房间不会伪造撤退击杀奖励。全部撤退人员已完成撤退或确认阵亡时，可提前结束撤退期，进入原推进倒计时。

多人验收：安排两名防守方留在旧区域，一名成功撤退；分别验证超时处决及敌方击杀，检查无救援状态、死亡提示、击杀卡和各一次补兵。成功撤退者在撤退期结束前折返旧区域，再分别被击杀和等待界外倒计时结束，确认不标记、不补兵；全员成功撤退时应提前进入推进倒计时。

## 开战与区域推进倒计时

首次部署后、开战前的移动锁定，以及拿下区域、撤退完成后的推进倒计时，均使用自定义绘制：沿用“撤退至下一区域 / 回到战斗区域”的白色字距、字号与居中位置，上方显示原说明文案，下方显示较大的剩余秒数。首次开战按玩法与阵营保留原文案；区域推进时进攻方显示“准备夺取下个阶段”，防守方显示“准备防守阵地”。

服务端每次显示秒数变化时同步实际剩余 tick，客户端持续递减；到零自动消失，移动解锁与区域推进仍由服务端原机制决定。两种倒计时各自清除，退出房间、断线、切换世界或玩家实体、进入营结算时清理显示；界外及撤退警告优先显示，避免同位置文字叠加。竞技／枪王模式死亡后的“等待重新部署”仍使用原显示方式。

0.1.8 增加了自定义倒计时数据包，当时协议为 `bf1-0.1.8-r2`；当前 0.1.15 协议为 `bf1-0.1.15`，客户端与服务端须同时使用本次构建。

## 进度条下方的兵力提示

双方共用进度条下方居中的白色提示行，字号为普通 HUD 字号的 **1.15 倍**，大于原小字号状态字幕；不占用原有战斗事件字幕行。最后一营（包括只配置一营的房间）开始时显示“最后的营”。提示依据服务器同步的进攻方实际兵力，使用绝对人数而非比例：

| 进攻方剩余兵力 | 进攻方文字 | 防守方文字 |
| --- | --- | --- |
| 21–50 | 剩余50名士兵 | 剩余50名攻击者 |
| 0–20 | 剩余20名士兵 | 剩余20名攻击者 |

两档提示不逐人更新，并优先替代“最后的营”。区域攻占补兵后按补充后的兵力重新选择提示，超过 50 时最后一营恢复显示“最后的营”，其他营不显示兵力提示。无限兵力不触发人数警告。HUD 不再显示“零兵力争夺”名称，也不再播放原按 50% / 20% 触发的兵力字幕；零兵力时保留 20 档提示，进度条上的实际数值仍显示 0。

## 零兵力争夺

原“背水一战”和“破釜沉舟”合并为“零兵力争夺”，沿用 `BT_DESPERATE` 音乐及原重生等待设置，HUD 显示实际兵力 **0**，时间显示 `--:--`。不再使用原三分钟/一分钟计时，也不受旧 `enableBackAgainstWall` 开关影响。

兵力归零时，先更新本阶段全部据点状态：已由进攻方完全占领的点允许保留；其余每个点必须仍有部分占领进度，或双方玩家同时处于该点的占领范围内进行争夺。防守方拥有满控制进度、且没有双方同时争夺的任意一个点，会结束本营。双方人数相同时仍算争夺，进度暂时停住不会退出；空点保留部分进度时仍算拉扯。只检查当前阶段的有效据点，不检查后续区域。

进入后可以继续战斗和部署，直到进攻方完全占领本阶段全部据点，或防守方完全控制任意一个点。占领成功走正常补兵和区域推进流程；失败走原营结算、战况简报及下一营准备流程，最后一个营失败才结束整场行动。最后一次死亡、攻占与超时同一服务器 tick 发生时，攻占成功优先，避免误判本营失败。

零兵力 HUD 可用 `/gdc debug preview hud breakthrough zerotroopcontest` 预览；原 `backtowall`、`burnboats` 调试入口也显示新状态。管理员 `exhaustBattalion` 仍直接结束本营以测试简报，不用于验证零兵力争夺。

## 战况演出时间轴（0.1.4）

管理员执行 `/gdc loadout room open`，会打开统一配置界面并切换到“房间数据”页。在左侧选择行动模式房间，在右侧配置列表的“规则”分类找到“战况时间轴”，点击“点击编辑”打开。也可点击该配置项的名称进入；其他玩法该项不可用，界面不再保留独立的时间轴按钮。返回时间轴的上一级界面时保留所选房间。编辑需要 OP 2 权限，配置保存在该房间的 `battalionConfig.timelines` 中，保存全部会直接写入房间文件，无需再执行 `saveRoom`。运行中的对局继续使用开局配置，下一场使用新配置；旧房间没有时间轴时，原镜头、遮罩及结果文字流程照常运行。

时间轴按本营结束后剩余的营数选择场景，进攻方拿下全部区域时优先选择整场获胜场景：

| 场景 | 配置键 | 三营房间中的触发时机 |
| --- | --- | --- |
| 剩 2 营 | `remaining_2` | 第一营耗尽，仍剩两营 |
| 最后营 | `last` | 第二营耗尽，下一营为最后一营 |
| 进攻方获胜 | `attacker_won` | 任意一营拿下全部区域 |
| 进攻方失败 | `attacker_lost` | 最后一营耗尽，未拿下全部区域 |

更多营数自动显示对应的“剩 X 营”场景。每个场景分别配置进攻方和防守方，各自拥有字幕轴与声音轴；两种整场结果搭配双方视角，覆盖四种胜负表现。减少总营数会保留暂时用不到的场景配置，之后增加营数可继续使用。

时间轴从结果停顿的第一刻开始。以简报 20 秒为例：

| 区间 | 阶段 | 时长 |
| --- | --- | --- |
| 0–3 秒 | 结果停顿 | 固定 3 秒 |
| 3–10 秒 | 镜头运动 | 固定 7 秒 |
| 10–30 秒 | 战况简报 | 房间配置的简报时长 |
| 30–31 秒 | 遮罩淡出 | 固定 1 秒 |
| 31–36 秒 | 阶段结果提示 | 固定 5 秒；换营显示攻势提示，整场结束显示行动胜负 |

所有场景的时间轴长度统一为“简报时长 + 16 秒”，因此示例中均为 36 秒。进攻方获胜/失败场景的最后一段标为“行动结果”，同样可以插入双方独立的字幕和声音。返回部署镜头、部署准备期不计入时间轴。顶部颜色区分各阶段，结果大字、区域边界与遮罩、阶段结果提示由固定演出时序显示，时间轴字幕显示在画面下方。

操作方法：

- 点击顶部场景名称展开下拉菜单，直接选择“剩 X 营 / 最后营 / 进攻方获胜 / 进攻方失败”；多营场景可滚动，支持上下键选择、回车确认、Esc 收起。点击“阵营”切换双方内容。
- 点击或拖动顶部阶段条/空白轨道调整播放指针；“插入字幕”在当前位置加入字幕，“选择声音”从客户端已加载的声音事件中选择资源。字幕位置被占用时会寻找后续可用空间。
- 拖动素材移动位置，拖动左右边缘调整起止时间；拖动按 0.1 秒吸附。也可选中素材，在“开始秒 / 持续秒”中输入精确时间，点击“应用修改”。编辑后的字段会在切换、插入、预览和保存时自动应用。
- 滚轮缩放，Shift + 滚轮平移。“播放 / 暂停 / 停止”用于本地字幕与声音预览；从中间播放时声音从相应偏移开始。预览不会消耗营数，也不会触发真实对局或移动所有玩家的镜头。
- 字幕正文使用 `\n` 换行。声音使用 `namespace:sound_event` 事件 ID，对应资源包 `sounds.json` 的事件；声音音量为 0–1，插入时在后台读取实际声音文件的长度，自动设置持续时间，并在声音素材条中显示秒数，按声音事件实际选中的文件及播放速度计算，向上取整到 0.05 秒；可继续手动裁剪。若完整声音超出当前插入位置剩余时长，则提示前移插入位置或延长房间简报，不会自动截短。资源缺失或无法解码时不会插入默认长度的占位声音。播放采用 Minecraft 的“声音/语音”音量类别。
- 完成后点击“保存全部”，一次保存所有场景及双方轨道。返回时有未保存改动会提示是否放弃；底部消息可悬停查看完整内容。

素材以所在阶段及阶段内偏移保存，持续时间不随简报时长缩放。例如在攻势提示开始插入的素材，简报由 20 秒改为 30 秒后整体后移 10 秒，自身持续时间保持不变。缩短简报导致素材越界或字幕重叠时会拒绝配置修改，需要先调整时间轴素材。双方字幕彼此独立，同一阵营字幕不允许重叠，声音允许同时播放；每条轨道最多 32 个素材，所有素材均须处于对应场景总时长以内。

字幕支持以下战报变量，正式播放前由服务端替换；编辑预览使用示例值：

| 写法 | 内容 |
| --- | --- |
| `{当前营数}` | 本次结束的是第几营 |
| `{总营数}` | 本场总营数 |
| `{剩余营数}` | 本营结束后尚未投入的营数 |
| `{本营攻占区域数}` | 本营完整攻占的区域数 |
| `{累计攻占区域数}` | 本场累计完整攻占的区域数 |
| `{本营作战秒数}` | 本营开始至结束经过的服务器时间秒数 |
| `{结束原因}` | 本营结算原因 |

正式演出的时间由服务端维护，在阶段切换、中途加入及周期同步时发送当前进度。客户端从当前字幕与声音偏移接续，已经结束的声音不补播；退出房间、结束演出或断开连接后停止时间轴声音。字幕及声音轨道只发送玩家所属阵营的内容。保存会校验打开编辑器时的房间配置版本，避免多名管理员相互覆盖。

本轮自动检查覆盖场景选择、阶段时长、字幕冲突与越界、战报替换、配置保存及旧房间兼容、编辑与播放包编解码、服务器播放时钟接续和音频偏移切片。多人同步、界面视觉及实际音频效果仍待实机验收。

## 行动结算触发时机（0.1.4）

行动模式取消独立的“对局结束展示位置”：房间配置界面不再显示该项，命令也不再接受设置；旧房间保留的该字段不会用于行动模式结算。最终演出和结算沿用开局读取的战况简报镜头，其他玩法继续使用自己的结算位置。

在房间编辑器的“结算”分类配置 `btSettlementTiming`，也可执行：

```text
/gdc room <房间ID> config breakthrough btSettlementTiming 对局结束时
/gdc room <房间ID> saveRoom
```

| 选项 | JSON 值 | 触发时刻 |
| --- | --- | --- |
| 对局结束时 | `MATCH_END` | 最后一次战斗结束、时间轴第 0 秒，先结算再进入 3 秒结果停顿 |
| 行动结果文字出现时（默认） | `ACTION_RESULT` | 遮罩淡出结束，开始显示“行动胜利 / 行动失败”时 |

胜负在战斗结束时立即冻结，配置只控制经验奖励、结算聊天消息及结算界面的触发时机。提前结算后房间进入 ENDING，但服务器继续推进完整的最终时间轴；不会清理当前字幕、声音或镜头，也不会启动原结算黑屏和额外镜头移动。结算界面使用右上方简洁结果提示及退出入口，为中央行动结果文字、下方字幕和战况遮罩留出空间。移动、开火、物品使用仍被锁定，鼠标和聊天继续可用。

结算只执行一次，退出后重连保留已处理的奖励记录；首次在结算后加入的玩家可看剩余演出，不领取本场奖励。重连的字幕、声音及结算界面按服务器当前时间恢复。经验计算中的对局时长冻结在战斗结束时，不把最终镜头和简报时间计入。

两种配置都在完整演出结束后开始 30 秒自动退房倒计时，避免长简报被提前中断。以 20 秒简报为例：立即结算发生在第 0 秒，延后结算发生在第 31 秒，演出均于第 36 秒结束，自动退房均于第 66 秒进行。该配置与营演出配置一起在下一场对局生效。

## 快速实机验证

在有双方玩家的测试房间开局后，可由管理员执行下列命令直接耗尽本营，避免反复制造死亡：

```text
/gdc room <房间ID> exhaustBattalion
```

命令需 OP 2 权限，仅在行动模式的作战阶段可用；会实际消耗当前营，请在测试对局使用。

建议依次确认：

- 同时包含存活、倒地和部署中的玩家，营结束后全部停止移动、攻击、战场交互及配装；管理员也应被锁定。鼠标、聊天输入及聊天记录滚动仍可使用，镜头飞行不受鼠标影响；跨演示阶段不应关闭已打开的聊天框。
- 双方分别看到正确结果文字，等待 3 秒后开始 7 秒飞行，镜头保留配置的朝向与俯仰。
- 攻到第三区再耗尽本营，确认只按顺序改变第一、第二区，双方红蓝相反，双方大本营从淡入开始就是对应阵营颜色，并且不随区域变色。
- 将简报设为 8 秒、45 秒比较，区域动画速度一致；准备倒计时都从返回到位开始。
- 简报时长结束后先退场 1 秒，再显示 5 秒攻势提示，然后开始返程；三营配置第一营结束后，进攻方显示“剩余2轮进攻”，第二营结束后显示“最后攻势”；防守方也按进攻方剩余营数显示“剩余2道防线 / 最后防线”，与剩余区域数无关。第三营结束后双方显示各自“行动胜利 / 行动失败”，同样持续 5 秒后结束演出。
- 返回后可以使用原部署界面、选出生点和调整配装；准备期不能提前出生。
- 在结果、飞行、简报、遮罩淡出、攻势提示和准备阶段分别重连/中途加入，确认跟随当前阶段并使用剩余时间。
- 第三营耗尽和攻占最后区域分别触发整场结算；双方在原攻势提示位置看到正确行动胜负。两种结算时机分别验证第 0 秒与行动结果文字出现时的消息、经验和退出入口；提前结算不打断演出，重连不重复发奖励，自动退房在演出结束后才开始倒计时。管理员中断对局/退出房间后锁定能解除。
- 每个区域真正进入作战时播放一次 `music.stage_begin`；换营后在准备结束、再次开战时也播放。同阶段的持续 HUD 刷新和部署切换不应重复播放。
- 将弹药箱与医疗箱装备的自动补全秒数设为正数并部署，投掷后无需靠近地面弹药箱，等待设定秒数即可恢复一件；达到配置数量后不再补全。设为 0 或禁用自动补全则不恢复。

兵力专项实测还需确认：阶段间增减参考阵营人数，检查上限更新和超额保留；分别用剩余 0/20/50/80 兵力攻占区域，核对保底、固定奖励及撤退奖励顺序；全部剩余点拉扯时耗尽兵力，保持争夺超过原阶段时间，再分别测试攻下全部据点和守方恢复任意一个据点的出口。

## 暂停期间的操作黑名单（0.1.9）

营结束至下一营作战恢复期间，以及整场结算期间，暂停状态仅限制具体战场行为。配装请求不再“全部拦截、逐项放行”：可以打开菜单、背包与配装界面、聊天、查看信息、调整个人设置、保存兵种／武器／配件选择和退出房间。原有权限、随机配装、房间限定装备和组队退房规则继续生效。未支持的协议动作仍按正常路由处理，不因暂停状态增加统一拒绝。

| 操作 | 演出期间 | 下一营部署准备期间 |
| --- | --- | --- |
| 查看界面、聊天、退出房间 | 正常处理 | 正常处理 |
| 保存下次部署配装 | 正常处理；不改变当前实体装备或能力 | 正常处理 |
| 切换阵营 | 禁止；保留演出阵营视角 | 按原部署规则处理 |
| 实际部署出生、重新部署、发起救援、放弃倒地 | 禁止 | 出生继续等待准备结束 |
| 停止救援、取消标记等清理 | 正常处理；仍检查原状态 | 正常处理 |
| 移动、开火、物品使用、修改实际背包、快捷栏切换、补给 | 禁止 | 沿用部署状态的操作限制 |

鼠标按钮和滚轮属于输入事件，不统一禁止。释放给 UI 的指针和已打开界面接收正常事件；原版攻击／物品使用、快捷栏切换和 TACZ 开火／换弹在对应战场执行入口拦截，已发出的原版战场数据包仍由服务端检查。固定演出镜头与 UI 鼠标分开管理。保留普通菜单后，切换简报阶段不再主动关闭配装或容器界面。

配装编辑读取下次部署的选择，战场兵种、救援能力、标记和 HUD 身份读取最近实际发放配装时的兵种快照。新配装发放后更新快照，离开房间、新对局和对局清理时清除；旧死亡流程清理不改变当前兵种。随机配装继续显示服务器选择的兵种。

HUD 也使用隐藏黑名单：隐藏明确识别的原版战斗 HUD、TACZ 枪械显示、生命条和已接入的击杀提示；保留演出、聊天、玩家列表、辅助字幕及未知普通叠加层。新模组若加入战斗 HUD，需要把对应叠加层登记为战斗显示项。


## 行动音乐与攻势提示音（0.1.12）

`music.stage_begin` 只在服务器认定的正式开战时间到达后触发，首次准备期间不提前播放；重复开战身份与重新部署不重播。

每次本营结果演出开始（含整场最终胜负），按玩家本轮结果直接播放一次胜负曲，不淡入、不循环：

| 本轮结果 | 音乐事件 | 复用素材 |
| --- | --- | --- |
| 胜利 | `gd656conquest:music.operation_victory` | `assets/gd656conquest/sounds/music/music_victory.ogg` |
| 失败 | `gd656conquest:music.operation_defeat` | `assets/gd656conquest/sounds/music/music_defeat.ogg` |

两个事件直接引用现有 OGG，无需独立背景文件；`loop_operation_intermission.ogg` 已删除。音乐从结果开始跨飞行、简报、提示和个人部署等待继续播放，各阶段不重播。正常素材长度约 35.544／40.368 秒，完成判定跟随实际音频播放状态，兼容资源包替换。

有下一营时，结果曲播完而玩家尚未开始部署，则直接播放现有 `loop.deploy_screen`，不淡入。开始部署时立即停止本轮结果曲／接续循环，不淡出；已部署的玩家不会在旧曲结束后误恢复部署音乐。服务器进入下一营 COMBAT 与个人实际部署分开处理。

最终营失败或拿下全部区域时，胜负曲同样在本营结果开始处播放。之后“行动胜利／失败”页面只更新显示，不再额外启动 `music.victory`／`music.defeat`。结算设为“对局结束时”或“行动结果出现时”，以及重复／重连的结算包，都不重新播放曲子。简报演出结束后尚未播完的曲子继续，自然结束后保持安静，不接部署循环；退出房间时清理。

时间轴有实际播放的额外声音时，仅将正在播放的胜负曲降至基础音量的 25%；所有额外声音结束后恢复至 100%。多个素材重叠期间保持压低，缺失、静音、结束或取消的声音不维持压低。仅有字幕不触发，编辑器本地预览不触发实时对局背景压低。音量更新只修改现有音乐对象，不重播、改变进度或修改时间轴音量；结果曲已结束时不会因为恢复音量而重新创建。接续部署循环不参与此压低策略。

进入攻势提示阶段，双方按进攻方剩余营数播放以下提示音一次，终局行动胜负提示不使用这两条攻势音：

| 提示 | 事件 ID | 资源包文件 |
| --- | --- | --- |
| 剩余 X 轮进攻／剩余 X 道防线，剩余营数≥2 | `gd656conquest:sfx.operation.next_assault` | `assets/gd656conquest/sounds/sounds/operation/ui_show_newobjective_wave.ogg` |
| 最后攻势／最后防线，剩余营数为 1 | `gd656conquest:sfx.operation.last_assault` | `assets/gd656conquest/sounds/sounds/operation/ui_show_objectivecomplete_wave.ogg` |

自动音频与房间时间轴独立，素材的起止、音量和字幕沿用配置。维护、匹配、断线、退出、换世界清理本轮音乐；死亡镜头清理不打断演出音乐。资源重载造成单曲停止后不从头重播，普通换营进入部署音乐，终局保持安静。本段为旧版行为；当前协议为 `bf1-0.1.15`，客户端和服务端须一起更新，具体音乐规则见 [行动音乐状态机](operations-music.md)。

验收建议：

- 普通换营双方分别听到胜／负曲，立即起播，准备界面不重新起曲；曲子结束后未部署则直接接部署循环。
- 在时间轴上插入单条、重叠、连续声音，确认背景降至 25%，全部结束恢复；提前结束素材或退出时不残留低音量。
- 只插字幕、静音素材、缺失资源和编辑器预览不触发实时背景压低，素材播放进度与音量保持配置。
- 结果曲播完前后分别部署，确认立即停止且不误恢复；恢复音量不重播已结束的曲子。
- 攻方胜利、守方胜利、单营、最后营与两种结算时机分别测试，确认最终页面不启动第二首音乐，曲子自然结束后不接部署循环。
- 首次准备不开战曲，正式开战触发一次；TACZ 1.1.7／1.1.8 射击兼容保持有效。

自动测试包含 12 组音乐场景与 7 项真实音乐对象／音量队列检查，覆盖直接起播音量、单次播放、部署接续、音量压低／恢复不重播、终局连续播放与结算不重复起曲。没有运行实机 OpenAL 试听，多人听感和资源包组合需上述实机验收。

## 据点布局与行动语音（0.1.13）

行动模式顶部据点队列中心从 GUI 坐标 Y=29 下移至 Y=62，放大的当前据点从 Y=67 下移至 Y=100，为兵力提示与 Y=43 的 HUD 字幕留出空间；部署视角和战斗视角共用此布局。

服务端根据真实扣兵、撤退名单和推进倒计时派发语音，使用现有本地声音数据包，同房间对应阵营所有在线玩家均能听到，包括等待部署的玩家。

| 触发条件 | 进攻方事件 | 防守方事件 |
| --- | --- | --- |
| 扣兵后剩余兵力 ≤ 当前上限的 50% | `voice.operation.kills_halfway_attackers` | `voice.operation.kills_halfway_defenders` |
| 扣兵后剩余兵力 ≤ 50 | `voice.operation.kills_togo50_attackers` | `voice.operation.kills_togo50_defenders` |
| 扣兵后剩余兵力 ≤ 20 | `voice.operation.kills_togo20_attackers` | `voice.operation.kills_togo20_defenders` |
| 防守玩家进入有效撤退目的区域 | — | 仅本人：`voice.operation.cleanup_retreatsuccess_defenders` |
| 旧区域撤退名单清空／撤退超时处理完毕，进入推进准备 | `voice.operation.cleanup_ended_attackers` | — |
| 推进倒计时结束，进入最后区域正式作战 | `voice.operation.winning` | `voice.operation.losing` |

事件命名空间均为 `gd656conquest`；每个事件对应 `assets/gd656conquest/sounds/voice/operation/vo_mp_mother_breakthrough_<事件末段>.ogg`。10 个 WAV 已转换为 Vorbis OGG，确认可解码后删除原件。

三档兵力提示按每营每阶段各一次去重。同一阶段补兵后再扣兵不重播；推进到下一阶段，或者下一营重启当前阶段，重新允许全部档位。半数按当前剩余兵力比较当前上限，不统计累计伤亡；奇数上限用精确半数比较。开局、小房间低兵力或改变上限不会自行播放；之后真实扣兵满足条件时播报，补兵恰好到 50 后再扣兵也能触发新阶段的 50 档。一次扣兵命中多个档位时保留各条语音，客户端依次播放。

撤退成功只有名单中的本人真正到达目的区域才触发一次；死亡、超时击杀、重新部署、退出、转队或离线移除不播放成功音。清理结束在进入推进倒计时处只触发一次，名单为空时可立即推进。最后区域语音只在推进倒计时结束后触发，不在撤退结束、准备期间、首次开局或换营重启最后区域时提前播放。

自动行动语音单次播放、不作距离衰减，使用独立顺序队列；同一玩家的这些语音彼此不叠播。进入本营结果演出、匹配／维护、退出房间、断线或换维度清理待播和当前自动语音。时间轴自定义音频沿用配置，不加入自动队列；国家士兵语音继续沿用 FrontVoice 联动。

实机验收：分别降到半数、50、20，再在同阶段补兵扣兵验证不重播；进入下一阶段补兵扣兵验证重新播放；下一营验证重置。检查个人到达、死亡、超时与重新部署的撤退表现，并确认清理结束在倒计时前、最后区域 winning／losing 在倒计时后；按不同 GUI 缩放检查顶部兵力文字、字幕与据点队列。

自动检查直接调用生产兵力状态，覆盖上限 1–1000、奇数半数、大整数、同阶段补兵、下一阶段重置及下一营重置；音乐对象测试同时检查自动播报请求保留、顺序、单次本地播放属性和队列清理。尚未在游戏中截图复核布局或实机试听。

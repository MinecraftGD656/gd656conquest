# 行动模式：营切换与战况简报（0.1.6）

房间列表中的原“突破 / Breakthrough”改为“行动 / Operations”。配置路径、玩法 ID 仍沿用 `breakthrough`，旧地图的区域、据点和部署位置可以继续使用。

## 配置镜头

与现有部署镜头和结算镜头的选择方式相同：管理员先站到希望作为简报镜头的位置，调整好朝向和俯仰角，再执行：

```text
/gdc room <房间ID> config breakthrough btBriefingViewPosition here
```

`here` 同时记录 X/Y/Z、yaw、pitch；也支持现有的 `x,y,z,yaw,pitch` 格式。坐标与其他镜头配置一致，X/Z 使用所在方块中心，Y 保留小数。建议选能俯瞰所有区域及双方大本营的高处，并朝地图中心看；镜头前方应能覆盖各区域完整边界。

另外三个参数：

```text
/gdc room <房间ID> config breakthrough btBattalionCount 3
/gdc room <房间ID> config breakthrough btBriefingSeconds 20
/gdc room <房间ID> config breakthrough btPreparationSeconds 10
/gdc room <房间ID> saveRoom
```

这些字段也接入原房间配置界面：简报镜头在“传送”分类，营数和时长在“规则”分类。

| 参数 | 默认值 | 范围 | 含义 |
| --- | --- | --- | --- |
| `btBattalionCount` | 3 | 1–10 | 进攻方总营数 |
| `btBriefingSeconds` | 20 秒 | 8–600 秒 | 到达简报镜头之后的演示时长，不包含往返飞行、退场淡出和攻势提示 |
| `btPreparationSeconds` | 10 秒 | 1–300 秒 | 返回部署位置后才开始的准备时间 |

旧 JSON 缺少营配置时自动使用默认值。多营房间启动前需要补设 `btBriefingViewPosition`；单营房间若未设置则使用当前区域部署镜头作为后备简报镜头。运行中的对局使用开局读取的营参数，新参数在下一场生效。

## 演示流程

本营兵力耗尽或当前区域进攻超时后，服务器立即暂停占领、伤害、复活／救援／部署推进，保留人物、倒地模型、尸体及载具供结果镜头和飞行观看。玩家本体在飞行期间留在原处；简报开始才清理旧玩家流程和本房间全部在场载具，清理不计死亡、击杀或比分，不触发载具爆炸。

1. 立即锁定移动、开火、物品使用等战场操作，保留鼠标与聊天，在原镜头停留 **3 秒**。防守方显示“我们赢了 / 成功防守本区域”，进攻方显示“我们输了 / 无法拿下本区域”。文字参考截图采用白色、加大字距、无描边的居中两行，上方大标题、下方小副标题；位置和大小按屏幕比例计算。
2. 用 **7 秒**平滑飞到简报位置，同时转到配置的角度。结果文字持续显示，直到飞行最后 **1 秒**才淡出，到达时完全隐藏。
3. 到位后才清理旧人物状态、尸体和载具，并开始 `btBriefingSeconds`。先用 **1 秒**淡入所有区域及双方大本营的边界与遮罩。大本营颜色始终按所属阵营显示：己方蓝色、敌方红色。
4. 各区域的起始遮罩统一表示防守方所有，然后按区域顺序，每区用 **0.5 秒**改变到进攻方所有；只改变已经完整拿下的区域。己方蓝色、敌方红色。攻到第三区时，进攻方先看到各区域全红，再依次将第一、第二区变蓝；第三区仍为红色。防守方看到相反配色。
5. 简报时长结束后，用 **1 秒**淡出全部边界、遮罩和简报标题。颜色保持最终战况，不回放变色动画。
6. 遮罩消失后，在画面中央偏上显示 **5 秒**“还有X波攻势”（剩余营数大于一）或“最后攻势”（只剩一营）。文字采用截图中的白色疏排样式，带短暂淡入淡出；期间镜头保持简报位置，战场操作仍然锁定，鼠标与聊天可以使用。
7. 提示结束后用 **2 秒**平滑返回当前区域的部署镜头。
8. 到位后清除简报画面，恢复原部署图标、边界、鼠标和配装入口，并开始准备倒计时。准备结束后使用原部署流程。

调长简报总时长只会延长最终战况画面的停留，不会减慢区域动画。六个区域的淡入和逐区变化共需 4 秒（淡入 1 秒、逐区变色共 3 秒）；简报时长仍保留原 8 秒下限。

换营保留已经完整占领的区域，当前未突破区域的据点归属与进度恢复到防守方，并按重新计算的上限补满新营兵力。区域时间配置 `btStageDurationMinutes` 可设为 `0` 关闭超时；零兵力争夺期间不受区域超时限制。

进攻方拿下全部区域，或最后一营耗尽时，仍先显示结果和简报；遮罩淡出后，在原攻势提示的位置显示“行动胜利”或“行动失败”，按玩家所属阵营判定，持续 5 秒，字号、字距及淡入淡出沿用攻势提示。全程留在战况简报镜头，不返回新营部署。拿下全部区域的开头结果文案相应改为攻方“成功拿下全部区域”、守方“无法守住本区域”。整场结算触发时机由下述配置决定。

## 兵力规则（0.1.2）

规则分类中的兵力参数：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `btTroopsPerPlayer` | 20 | 每位参考阵营玩家提供的兵力，支持正数小数 |
| `btTroopBalanceReference` | 根据防守方计算 | 也可选择根据进攻方计算 |
| `btMaxAttackTroops` | 250 | 人数计算结果允许的最大上限，须为正整数 |
| `btStageTroopReward` | 50 | 每次完整攻占区域发放的固定补兵，允许设为 0 |
| `btTroopGainPerDefenderKill` | 3 | 清理撤退守军时，每次符合条件的击杀补兵 |

```text
/gdc room <房间ID> config breakthrough btTroopsPerPlayer 20
/gdc room <房间ID> config breakthrough btTroopBalanceReference 根据防守方计算
/gdc room <房间ID> config breakthrough btMaxAttackTroops 250
/gdc room <房间ID> config breakthrough btStageTroopReward 50
/gdc room <房间ID> config breakthrough btTroopGainPerDefenderKill 3
/gdc room <房间ID> saveRoom
```

上限 = `min(最大兵力上限, 向上取整(参考阵营人数 × 每人提供兵力数))`。人数沿用原规则，统计房间内属于参考阵营的参战玩家，包括倒地、死亡和部署中的成员；观战人员不计入参考阵营。开局、新营准备开始时计算上限并补满。区域攻占成功时按当时人数计算下一阶段上限，实际进入下一阶段时不再计算，也不再次补兵。阶段作战中加入或退出不会立即改变本阶段的上限，在下次区域攻占或新营开始时生效。

区域攻占成功后的固定顺序：

1. 更新上限。上限增加不自动补兵；上限降低也不裁掉已有的超额兵力。
2. 当前兵力不足 50 时，先补至 `min(50, 新上限)`；如果当前兵力已经超出新上限，则原样保留。
3. 发放 `btStageTroopReward`，仅补充新上限以内的空缺。
4. 后续清理撤退守军期间逐次发放击杀奖励，同样不会溢出上限或裁掉原有超额兵力。

例如新上限为 200、攻占时剩 20，则先补至 50，再增加默认 50，得到 100；之后击杀五名撤退守军增加 15，得到 115。若新上限为 70，同样剩 20，则最终只能补至 70。若已有 160、上限降到 100，则仍保留 160，后续自然消耗至低于上限后才允许补兵。区域奖励仅发放一次，进入撤退、推进倒计时和下一阶段不会重复领取。

进攻方倒地不扣兵力，成功救援不扣兵力，确认死亡在正常作战阶段扣 1。防守方普通死亡不减少进攻方兵力。撤退和推进倒计时期间进攻方死亡不扣兵力；本次尚未成功撤退的防守方，因撤退超时或被进攻方击杀而确认死亡时提供一次奖励；已成功撤退后折返不提供奖励。换营清理、传送和重生不扣兵力。

旧房间 JSON 的 `maxAttackTroopsAt12Players` 读取时自动除以 12，转换为 `troopsPerPlayer`；已有的明确计算基准和击杀奖励保留，缺少的新字段使用默认值。保存后只写新字段，不会反复除以 12。原 `btMaxAttackTroopsAt12Players` 配置入口移除，改用 `btTroopsPerPlayer`；不要直接把旧数值填入新配置。

## 撤退规则（0.1.3）

区域攻占后，记录此刻旧区域内存活且不在死亡/部署流程中的防守方作为本次撤退人员。未完成撤退期间保留双方可见的追踪标记，画面显示两行白色提示：上行“撤退至下一区域”、下行剩余秒数。字号、字距、阴影和位置与现有“回到战斗区域”警告共用同一绘制方式，不再使用原生标题或长时限动作栏提示。

到达下一阶段及其后的合法防守区域、或防守方大本营，即完成本次撤退。完成状态不可逆；重新进入旧区域按界外处理，显示原界外警告，不会重新获得撤退标记，也不会提供撤退补兵。界外被进攻方击杀保留原来源，界外倒计时耗尽沿用“逃兵”处决，均沿用现有禁止救援规则。

| 情况 | 死亡提示与来源 | 救援 | 进攻方补兵 |
| --- | --- | --- | --- |
| 撤退时限结束，仍未完成撤退 | 立即处决，显示“撤退失败”；无击杀者、无击杀卡，不归因于最近攻击者 | 不可救援 | 每人一次 `btTroopGainPerDefenderKill`，默认 3 |
| 撤退人员被进攻方击杀 | 显示原击杀者、武器等来源，同时在上方显示“撤退失败” | 不可救援 | 同上 |
| 撤退成功后折返旧区域 | 原界外被击杀或“逃兵”流程 | 沿用界外禁止救援 | 无撤退奖励 |

补兵仍受攻占时已更新的下一阶段兵力上限限制；已有超额兵力不会被裁掉。自然伤害、管理员处决、重新部署和退出房间不会伪造撤退击杀奖励。全部撤退人员已完成撤退或确认阵亡时，可提前结束撤退期，进入原推进倒计时。

多人验收：安排两名防守方留在旧区域，一名成功撤退；分别验证超时处决及敌方击杀，检查无救援状态、死亡提示、击杀卡和各一次补兵。成功撤退者在撤退期结束前折返旧区域，再分别被击杀和等待界外倒计时结束，确认不标记、不补兵；全员成功撤退时应提前进入推进倒计时。

## 零兵力争夺

原“背水一战”和“破釜沉舟”合并为“零兵力争夺”，沿用 `BT_DESPERATE` 音乐及原重生等待设置，HUD 显示实际兵力 **0**，时间显示 `--:--`。不再使用原三分钟/一分钟计时，也不受旧 `enableBackAgainstWall` 开关影响。

兵力归零时，先更新本阶段全部据点状态：已由进攻方完全占领的点允许保留；其余每个点必须仍有部分占领进度，或双方玩家同时处于该点的占领范围内进行争夺。防守方拥有满控制进度、且没有双方同时争夺的任意一个点，会结束本营。双方人数相同时仍算争夺，进度暂时停住不会退出；空点保留部分进度时仍算拉扯。只检查当前阶段的有效据点，不检查后续区域。

进入后可以继续战斗和部署，直到进攻方完全占领本阶段全部据点，或防守方完全控制任意一个点。占领成功走正常补兵和区域推进流程；失败走原营结算、战况简报及下一营准备流程，最后一个营失败才结束整场行动。最后一次死亡、攻占与超时同一服务器 tick 发生时，攻占成功优先，避免误判本营失败。

零兵力 HUD 可用 `/gdc debug preview hud breakthrough zerotroopcontest` 预览；原 `backtowall`、`burnboats` 调试入口也显示新状态。管理员 `exhaustBattalion` 仍直接结束本营以测试简报，不用于验证零兵力争夺。

## 战况演出时间轴（0.1.4）

管理员执行 `/gdc loadout room open`，会打开统一配置界面并切换到“房间数据”页。在左侧选择行动模式房间，在右侧配置列表的“规则”分类找到“战况时间轴”，点击“点击编辑”打开。也可点击该配置项的名称进入；其他玩法该项不可用，界面不再保留独立的时间轴按钮。返回时间轴的上一级界面时保留所选房间。编辑需要 OP 2 权限，配置保存在该房间的 `battalionConfig.timelines` 中，保存全部会直接写入房间文件，无需再执行 `saveRoom`。运行中的对局继续使用开局配置，下一场使用新配置；旧房间没有时间轴时，原镜头、遮罩及结果文字流程照常运行。

时间轴按本营结束后剩余的营数选择场景，进攻方拿下全部区域时优先选择整场获胜场景：

| 场景 | 配置键 | 三营房间中的触发时机 |
| --- | --- | --- |
| 剩 2 营 | `remaining_2` | 第一营耗尽，仍剩两营 |
| 最后营 | `last` | 第二营耗尽，下一营为最后一营 |
| 进攻方获胜 | `attacker_won` | 任意一营拿下全部区域 |
| 进攻方失败 | `attacker_lost` | 最后一营耗尽，未拿下全部区域 |

更多营数自动显示对应的“剩 X 营”场景。每个场景分别配置进攻方和防守方，各自拥有字幕轴与声音轴；两种整场结果搭配双方视角，覆盖四种胜负表现。减少总营数会保留暂时用不到的场景配置，之后增加营数可继续使用。

时间轴从结果停顿的第一刻开始。以简报 20 秒为例：

| 区间 | 阶段 | 时长 |
| --- | --- | --- |
| 0–3 秒 | 结果停顿 | 固定 3 秒 |
| 3–10 秒 | 镜头运动 | 固定 7 秒 |
| 10–30 秒 | 战况简报 | 房间配置的简报时长 |
| 30–31 秒 | 遮罩淡出 | 固定 1 秒 |
| 31–36 秒 | 阶段结果提示 | 固定 5 秒；换营显示攻势提示，整场结束显示行动胜负 |

所有场景的时间轴长度统一为“简报时长 + 16 秒”，因此示例中均为 36 秒。进攻方获胜/失败场景的最后一段标为“行动结果”，同样可以插入双方独立的字幕和声音。返回部署镜头、部署准备期不计入时间轴。顶部颜色区分各阶段，原有结果大字、区域遮罩和阶段结果提示继续由原流程显示，时间轴字幕显示在画面下方。

操作方法：

- 点击顶部场景名称展开下拉菜单，直接选择“剩 X 营 / 最后营 / 进攻方获胜 / 进攻方失败”；多营场景可滚动，支持上下键选择、回车确认、Esc 收起。点击“阵营”切换双方内容。
- 点击或拖动顶部阶段条/空白轨道调整播放指针；“插入字幕”在当前位置加入字幕，“选择声音”从客户端已加载的声音事件中选择资源。字幕位置被占用时会寻找后续可用空间。
- 拖动素材移动位置，拖动左右边缘调整起止时间；拖动按 0.1 秒吸附。也可选中素材，在“开始秒 / 持续秒”中输入精确时间，点击“应用修改”。编辑后的字段会在切换、插入、预览和保存时自动应用。
- 滚轮缩放，Shift + 滚轮平移。“播放 / 暂停 / 停止”用于本地字幕与声音预览；从中间播放时声音从相应偏移开始。预览不会消耗营数，也不会触发真实对局或移动所有玩家的镜头。
- 字幕正文使用 `\n` 换行。声音使用 `namespace:sound_event` 事件 ID，对应资源包 `sounds.json` 的事件；声音音量为 0–1，插入时在后台读取实际声音文件的长度，自动设置持续时间，并在声音素材条中显示秒数，按声音事件实际选中的文件及播放速度计算，向上取整到 0.05 秒；可继续手动裁剪。若完整声音超出当前插入位置剩余时长，则提示前移插入位置或延长房间简报，不会自动截短。资源缺失或无法解码时不会插入默认长度的占位声音。播放采用 Minecraft 的“声音/语音”音量类别。
- 完成后点击“保存全部”，一次保存所有场景及双方轨道。返回时有未保存改动会提示是否放弃；底部消息可悬停查看完整内容。

素材以所在阶段及阶段内偏移保存，持续时间不随简报时长缩放。例如在攻势提示开始插入的素材，简报由 20 秒改为 30 秒后整体后移 10 秒，自身持续时间保持不变。缩短简报导致素材越界或字幕重叠时会拒绝配置修改，需要先调整时间轴素材。双方字幕彼此独立，同一阵营字幕不允许重叠，声音允许同时播放；每条轨道最多 32 个素材，所有素材均须处于对应场景总时长以内。

字幕支持以下战报变量，正式播放前由服务端替换；编辑预览使用示例值：

| 写法 | 内容 |
| --- | --- |
| `{当前营数}` | 本次结束的是第几营 |
| `{总营数}` | 本场总营数 |
| `{剩余营数}` | 本营结束后尚未投入的营数 |
| `{本营攻占区域数}` | 本营完整攻占的区域数 |
| `{累计攻占区域数}` | 本场累计完整攻占的区域数 |
| `{本营作战秒数}` | 本营开始至结束经过的服务器时间秒数 |
| `{结束原因}` | 本营结算原因 |

正式演出的时间由服务端维护，在阶段切换、中途加入及周期同步时发送当前进度。客户端从当前字幕与声音偏移接续，已经结束的声音不补播；退出房间、结束演出或断开连接后停止时间轴声音。字幕及声音轨道只发送玩家所属阵营的内容。保存会校验打开编辑器时的房间配置版本，避免多名管理员相互覆盖。

本轮自动检查覆盖场景选择、阶段时长、字幕冲突与越界、战报替换、配置保存及旧房间兼容、编辑与播放包编解码、服务器播放时钟接续和音频偏移切片。多人同步、界面视觉及实际音频效果仍待实机验收。

## 行动结算触发时机（0.1.4）

行动模式取消独立的“对局结束展示位置”：房间配置界面不再显示该项，命令也不再接受设置；旧房间保留的该字段不会用于行动模式结算。最终演出和结算沿用开局读取的战况简报镜头，其他玩法继续使用自己的结算位置。

在房间编辑器的“结算”分类配置 `btSettlementTiming`，也可执行：

```text
/gdc room <房间ID> config breakthrough btSettlementTiming 对局结束时
/gdc room <房间ID> saveRoom
```

| 选项 | JSON 值 | 触发时刻 |
| --- | --- | --- |
| 对局结束时 | `MATCH_END` | 最后一次战斗结束、时间轴第 0 秒，先结算再进入 3 秒结果停顿 |
| 行动结果文字出现时（默认） | `ACTION_RESULT` | 遮罩淡出结束，开始显示“行动胜利 / 行动失败”时 |

胜负在战斗结束时立即冻结，配置只控制经验奖励、结算聊天消息及结算界面的触发时机。提前结算后房间进入 ENDING，但服务器继续推进完整的最终时间轴；不会清理当前字幕、声音或镜头，也不会启动原结算黑屏和额外镜头移动。结算界面使用右上方简洁结果提示及退出入口，为中央行动结果文字、下方字幕和战况遮罩留出空间。移动、开火、物品使用仍被锁定，鼠标和聊天继续可用。

结算只执行一次，退出后重连保留已处理的奖励记录；首次在结算后加入的玩家可看剩余演出，不领取本场奖励。重连的字幕、声音及结算界面按服务器当前时间恢复。经验计算中的对局时长冻结在战斗结束时，不把最终镜头和简报时间计入。

两种配置都在完整演出结束后开始 30 秒自动退房倒计时，避免长简报被提前中断。以 20 秒简报为例：立即结算发生在第 0 秒，延后结算发生在第 31 秒，演出均于第 36 秒结束，自动退房均于第 66 秒进行。该配置与营演出配置一起在下一场对局生效。

## 快速实机验证

在有双方玩家的测试房间开局后，可由管理员执行下列命令直接耗尽本营，避免反复制造死亡：

```text
/gdc room <房间ID> exhaustBattalion
```

命令需 OP 2 权限，仅在行动模式的作战阶段可用；会实际消耗当前营，请在测试对局使用。

建议依次确认：

- 同时包含存活、倒地和部署中的玩家，营结束后全部停止移动、攻击、战场交互及配装；管理员也应被锁定。鼠标、聊天输入及聊天记录滚动仍可使用，镜头飞行不受鼠标影响；跨演示阶段不应关闭已打开的聊天框。
- 双方分别看到正确结果文字，等待 3 秒后开始 7 秒飞行，镜头保留配置的朝向与俯仰。
- 攻到第三区再耗尽本营，确认只按顺序改变第一、第二区，双方红蓝相反，双方大本营从淡入开始就是对应阵营颜色，并且不随区域变色。
- 将简报设为 8 秒、45 秒比较，区域动画速度一致；准备倒计时都从返回到位开始。
- 简报时长结束后先退场 1 秒，再显示 5 秒攻势提示，然后开始返程；三营配置第一营后显示“还有2波攻势”，第二营后显示“最后攻势”，第三营后显示“行动胜利 / 行动失败”，同样持续 5 秒后结束演出。
- 返回后可以使用原部署界面、选出生点和调整配装；准备期不能提前出生。
- 在结果、飞行、简报、遮罩淡出、攻势提示和准备阶段分别重连/中途加入，确认跟随当前阶段并使用剩余时间。
- 第三营耗尽和攻占最后区域分别触发整场结算；双方在原攻势提示位置看到正确行动胜负。两种结算时机分别验证第 0 秒与行动结果文字出现时的消息、经验和退出入口；提前结算不打断演出，重连不重复发奖励，自动退房在演出结束后才开始倒计时。管理员中断对局/退出房间后锁定能解除。
- 每个区域真正进入作战时播放一次 `music.stage_begin`；换营后在准备结束、再次开战时也播放。同阶段的持续 HUD 刷新和部署切换不应重复播放。
- 将弹药箱与医疗箱装备的自动补全秒数设为正数并部署，投掷后无需靠近地面弹药箱，等待设定秒数即可恢复一件；达到配置数量后不再补全。设为 0 或禁用自动补全则不恢复。

兵力专项实测还需确认：阶段间增减参考阵营人数，检查上限更新和超额保留；分别用剩余 0/20/50/80 兵力攻占区域，核对保底、固定奖励及撤退奖励顺序；全部剩余点拉扯时耗尽兵力，保持争夺超过原阶段时间，再分别测试攻下全部据点和守方恢复任意一个据点的出口。

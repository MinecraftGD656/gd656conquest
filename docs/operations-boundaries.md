# 行动模式部署与战区边界（0.1.18）

步兵和地面载具使用随前线推进的两区范围。进攻方允许进入当前争夺阶段及紧邻上一阶段；防守方允许进入当前争夺阶段及紧邻下一阶段。双方本营只作为阶段序列两端的相邻区域，不再永久开放。

例如地图物理区域依次为 A、B、C、D、E、F，A 是进攻方本营，F 是防守方本营，B～E 为可争夺区域：

| 当前争夺区 | 进攻方合法范围 | 防守方合法范围 |
| --- | --- | --- |
| B | A、B | B、C |
| C | B、C | C、D |
| D | C、D | D、E |
| E | D、E | E、F |

配置仍沿用原结构：`campABaseBoundary` 和 `campBBaseBoundary` 是双方本营；`stageABoundary`～`stageFBoundary` 是已有争夺阶段。上述示例的物理 B 区对应第一个争夺阶段，而不是要求把本营录入争夺阶段。没有新增地图配置字段。

## 几何与出界

服务器只检查玩家 X/Z 是否落在本方开放区域所绘制的任意有效多边形内，多边形至少需要三个顶点。两个区域之间的空隙不会自动连接或填补；缺失、无效的多边形不会开放任何额外空间。地图绘制者负责道路、桥梁及撤退路线的边界衔接。

原出界方块、高度限制、步兵与载具的处罚时限和出界死亡流程继续生效。水平战区外的位置按原倒计时处罚；回到合法范围清除倒计时。

飞行载具继续使用原水平活动范围、飞行边界外扩和高度/处罚配置，不套用新的两区范围。离开飞行载具后（包括跳伞）立即按步兵范围判断。部署飞行载具也保留原阶段开放规则；地面载具在选择和实际生成/登乘时都检查本方新范围。

## 失守、撤退和推进

以 B 失守、下一阶段为 C 为例：

1. 防守方普通活动与新部署范围立即前移至 C、D。旧 B 区的撤退名单成员额外保留 B 区临时通行资格，不能通过其他人、信标或载具向 B 区增援。
2. 撤退成员到达 C 或 D 即完成撤退；取消 B 区临时资格，折返 B 按出界处理。恢复与补给仍服从现有撤退成功恢复配置。
3. 未完成撤退者保留原跟踪标记、撤退倒计时、失败处决和奖励规则。飞行载具保留原撤退目的范围。
4. 清理期间及推进倒计时期间，进攻方范围仍是 A、B，不能提前进入或部署到 C。
5. 推进倒计时结束、C 正式开战时，进攻方范围切为 B、C，A 本营关闭；防守方继续使用 C、D。

换营保留当前前线，重开本阶段时依当前阶段重新计算双方范围。

## 部署入口与实际出生坐标

本营、据点、小队队友、信标、地面载具都受本方部署范围限制。部署不继承存活撤退人员的临时资格。

- 攻方本营仅在第一个争夺阶段开放；守方本营仅在最后争夺阶段（含该阶段前的守方撤退/准备）开放。实际坐标仍需落在本方合法多边形内。
- 据点阶段资格与本方部署阶段一致；守方在撤退/推进期使用下一阶段及其后方相邻阶段。内外出生点选择仍沿用现有完全控制、16 格据点威胁检查等规则。
- 候选出生坐标先按合法范围过滤，再执行原 8 格避敌和最远点回退；绝不使用范围外坐标补足候选。
- 队友、信标位置在选择及执行时验证；界外信标不会因此消耗部署次数。地面载具生成/登乘前再次检查实际位置。
- 出生过渡结束时再次校验步兵落点，防止过渡期间推进导致旧坐标失效。失败返回部署界面。
- 失效目标可以恢复为合法的默认本营/据点供重新确认；没有合法默认目标时保留部署界面。不会自动选择其他载具，也不会回退到旧本营、征服模式出生点、死亡坐标或房间等待点。

部署 HUD 的区域线反映当前范围与个人撤退例外；不合法本营/队友/信标入口不显示为可用目标。据点保留真实归属和占领进度，服务器通过 `DEPLOY_BLOCKED` 标志禁止客户端点击不可用据点，服务端仍独立验证。

## 构建与验证

版本与严格协议均为 `bf1-0.1.18`，客户端、服务端须同时更新。

本地 `tools/battalion-tests` 回归包含六区范围表、各阶段本营开放、撤退权限与新部署隔离、推进切换、候选过滤、旧兜底禁止、未绘制空隙与空多边形、旧飞行范围，以及据点可部署标志编解码。多人实机仍需检查各地图边界与路线、载具后端、离机跳伞、跨阶段出生镜头及撤退标记。

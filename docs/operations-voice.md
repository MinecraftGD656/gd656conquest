# 区域与撤退播报（0.1.15）

客户端与服务端均须更新至0.1.15，协议 `bf1-0.1.15`。区域被完全拿下时，按服务端实际撤退名单分发新语音，当前区域为最终区域则不发本轮六条新播报，直接进入结果演出；现有EOR和结果阶段清理保留。

## 触发与分发

下列文件统一位于 `assets/gd656conquest/sounds/voice/operation/`，文件名前缀均为 `vo_mp_mother_breakthrough_`，扩展名为`.ogg`，声音事件统一为 `gd656conquest:voice.operation.<末段>`。

| 时机 | 接收方 | 末段 |
| --- | --- | --- |
| 非最终区域全部据点被拿下 | 进攻方所有在线玩家 | sector_taken |
| 上一句实际播完后等待20个客户端tick（1秒），且清理仍在进行 | 进攻方原播报接收者 | cleanup_initiate_attackers |
| 开始撤退清理 | 当时处于撤退名单中的防守方 | cleanup_initiate_defenders |
| 非最终区域被拿下 | 其余在线防守方，包含后方／死亡／等待部署玩家 | sector_fallen |
| 撤退时间从>10秒降至≤10秒，时间尚未耗尽且名单仍非空 | 进攻方所有在线玩家 | cleanup_togofew_attackers |
| 同一提醒时刻 | 当前仍在撤退名单中的防守方 | cleanup_togofew_defenders |

没有撤退名单或关闭撤退时，仅发sector_taken／sector_fallen，跳过开始清理与10秒提醒。撤退配置≤10秒时跳过10秒提醒；每次撤退只触发一次，跳过精确10秒帧也不会漏播，名单已经为空或时间耗尽不播。已有的撤退成功、清理结束、最后区域开战及兵力语音继续沿用。

## 播放顺序与取消

sector_taken后一句的延迟从SoundManager确认当前声音自然结束时开始，不根据固定WAV时长或服务器捕获时间估算，因此适配资源包替换。延迟期间保持1秒间隔；仍有清理任务才播放后一句。

新增播报带有房间、对局、营、区域和接收身份。服务端在名单、阵营或阶段变化时同步有效状态；客户端在入队、起播和间隔结束时检查。防守方到达、死亡或重新部署后，未播或正在播的撤退指令／提醒取消；个人撤退成功语音保留。清理结束取消撤退指令与提醒，已产生的区域拿下／失守播报可继续到推进倒计时，进入下一地区后过期。

区域新播报优先于排队中的普通兵力语音，10秒提醒优先级更高；同优先级保留先后顺序，不叠播，不打断仍有效的当前语音。若提醒已经到来，而进攻方的开始清理指令尚未播放，取消旧指令，避免提醒后才宣布开始清理。结果演出、退房、断线及换维度继续清空全部自动播报。

六个原WAV已转为Vorbis OGG并逐一解码检查，随后删除对应WAV原件。自动检查覆盖身份分流、最终区域排除、真实完成后的间隔、阶段失效、优先级、短撤退、阈值跨越、提醒去重和网络往返。尚未实机试听。
